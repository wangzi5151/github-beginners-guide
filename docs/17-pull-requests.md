# Pull Request 协作

## 什么是 Pull Request？

Pull Request（PR）是向项目贡献代码的标准方式。它允许：
- 代码审查
- 讨论变更
- 自动化检查
- 安全合并

## PR 工作流程图

```
1. Fork 仓库（外部贡献）
     ↓
2. 创建功能分支
     ↓
3. 修改代码并提交
     ↓
4. 推送到远程
     ↓
5. 创建 Pull Request（网页操作）
     ↓
6. 代码审查（网页操作）
     ↓
7. 合并（网页操作）
```

## 创建 Pull Request（图文详解）

### 第 1 步：推送分支到远程

在终端中执行：

```bash
# 确保在功能分支上
git checkout feature-new-button

# 推送到远程
git push -u origin feature-new-button
```

### 第 2 步：打开创建 PR 页面

**方法一：从提示信息创建**
1. 推送后，终端会显示一个链接
2. 复制链接在浏览器中打开

**方法二：手动创建**
1. 打开仓库页面
2. 点击 **Pull requests** 标签
3. 点击绿色的 **New pull request** 按钮

```
┌─────────────────────────────────────────────┐
│  Pull requests                               │
│                                             │
│  [New pull request]  ← 点击这个按钮          │
│                                             │
│  No pull requests                            │
└─────────────────────────────────────────────┘
```

### 第 3 步：选择分支

1. **base:** 选择目标分支（通常是 `main`）
2. **compare:** 选择你的功能分支

```
┌─────────────────────────────────────────────┐
│  Compare changes                             │
│                                             │
│  base: [main ▼]  ← 目标分支                  │
│     ...                                     │
│  compare: [feature-new-button ▼]  ← 你的分支 │
│                                             │
│  [Create pull request]                       │
└─────────────────────────────────────────────┘
```

### 第 4 步：填写 PR 信息

1. **Title**（标题）：简短描述变更内容
2. **Description**（描述）：详细说明变更内容
3. 点击 **Create pull request**

```
┌─────────────────────────────────────────────┐
│  Open a pull request                         │
│                                             │
│  base: main  ←  compare: feature-new-button │
│                                             │
│  Title: [feat: 添加新按钮功能           ]     │
│                                             │
│  Description:                                │
│  ┌─────────────────────────────────────┐    │
│  │ ## 变更说明                         │    │
│  │ 添加了一个新按钮                     │    │
│  │                                     │    │
│  │ ## 变更类型                         │    │
│  │ - [x] 新功能 (feat)                 │    │
│  │ - [ ] Bug 修复 (fix)                │    │
│  └─────────────────────────────────────┘    │
│                                             │
│  ☑ Reviewers: [添加审查者]                  │
│  ☑ Assignees: [添加负责人]                  │
│  ☑ Labels: [添加标签]                       │
│                                             │
│        [Create pull request]                │
└─────────────────────────────────────────────┘
```

### 第 5 步：PR 创建成功

创建成功后，页面会跳转到 PR 详情页，显示：
- PR 状态
- 代码差异
- 审查状态
- CI 检查状态

## 代码审查（网页操作）

### 审查 PR

1. 在 PR 页面点击 **Files changed** 标签
2. 查看代码差异
3. 点击行号添加评论

```
┌─────────────────────────────────────────────┐
│  Files changed  (3)                          │
│                                             │
│  ─ src/button.ts (+5 -2)                    │
│                                             │
│     1  │ const button = () => {             │
│  -   2  │   return <button>Click</button>;  │
│  +   2  │   return <button className="new"> ││
│  +   3  │     Click                         │
│  +   4  │   </button>;                      │
│     5  │ };                                 │
│                                             │
│  点击行号旁边的 + 可以添加评论                  │
└─────────────────────────────────────────────┘
```

### 添加审查意见

1. 在代码行旁边点击 **+** 按钮
2. 在弹出框中输入评论
3. 点击 **Start review** 或 **Add single comment**

```
┌─────────────────────────────────────┐
│  💬 Leave a comment                  │
│                                     │
│  这里建议使用更具体的类名              │
│                                     │
│  ○ Comment  ← 仅评论                │
│  ○ Approve  ← 批准                  │
│  ○ Request changes ← 要求修改        │
│                                     │
│     [Start review]                  │
└─────────────────────────────────────┘
```

### 审查完成后

1. 点击页面右上角的 **Review changes**
2. 选择审查结果：
   - **Comment**：仅评论，不阻止合并
   - **Approve**：批准 PR
   - **Request changes**：要求修改，阻止合并
3. 点击 **Submit review**

## 合并 PR（网页操作）

### 合并条件

在合并之前，确保：
- ✅ 所有审查者已批准
- ✅ CI 检查通过
- ✅ 没有冲突

### 合并操作

1. 在 PR 页面底部找到合并区域
2. 选择合并方式
3. 点击 **Merge pull request**
4. 输入合并信息（可选）
5. 点击 **Confirm merge**

```
┌─────────────────────────────────────────────┐
│  Pull request successfully merged            │
│                                             │
│  ┌─────────────────────────────────────┐    │
│  │  ○ Create a merge commit            │    │

│  │                                     │    │

│  │    压缩为一个提交                    │    │
│  │                                     │    │
│  │  ○ Rebase and merge                 │    │
│  │    线性历史                          │    │
│  └─────────────────────────────────────┘    │
│                                             │
│  Merge message:                             │

└─────────────────────────────────────────────┘
```

## 合并后清理（网页操作）

合并 PR 后，可以删除功能分支：

1. 在 PR 页面底部，点击 **Delete branch**
2. 确认删除

```
┌─────────────────────────────────────────────┐
│  Pull request successfully merged            │
│                                             │
│  ✓ branch feature-new-button deleted         │
│                                             │
└─────────────────────────────────────────────┘
```

## PR 最佳实践

1. **保持小而专注**：一个 PR 只做一件事
2. **清晰的标题和描述**：让审查者快速理解
3. **关联 Issue**：说明解决什么问题
4. **及时响应审查**：不要让 PR 放太久
5. **测试充分**：确保代码质量

## 实践练习

### 练习：创建并合并一个 PR

**任务 1：创建仓库和分支**
1. 在 GitHub 创建一个新仓库 `pr-practice`
2. 克隆到本地
3. 创建新分支 `feature-add-readme`

**任务 2：修改并推送**
1. 修改 README.md 文件
2. 提交并推送到远程

**任务 3：创建 PR**
1. 在 GitHub 页面点击 **Pull requests**
2. 点击 **New pull request**
3. 填写标题和描述
4. 点击 **Create pull request**

**任务 4：审查 PR**
1. 查看代码差异
2. 添加评论
3. 点击 **Approve**

**任务 5：合并 PR**
1. 点击 **Merge pull request**
2. 点击 **Confirm merge**
3. 删除功能分支

**验证方法：**
- PR 状态显示为 "Merged"（紫色）
- 代码已合并到 main 分支
