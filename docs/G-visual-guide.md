# Git 可视化指南（图解）

## Git 三大区域

```
┌─────────────────────────────────────────────────────────────┐
│                        工作区                                 │
│                  (Working Directory)                         │
│                                                             │
│   你编辑文件的地方，所有修改首先在这里                         │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          │  git add
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                        暂存区                                 │
│                    (Staging Area)                             │
│                                                             │
│   准备提交的修改，像一个"草稿区"                              │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          │  git commit
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                        仓库                                   │
│                    (Repository)                               │
│                                                             │
│   已提交的历史记录，永久保存                                   │
└─────────────────────────────────────────────────────────────┘
```

## 文件状态流转

```
                    新文件
                      │
                      ▼
┌─────────────────────────────────────────────────────────────┐
│                    Untracked                                  │
│               (未跟踪状态)                                    │
│                                                             │
│   Git 不知道这个文件的存在                                      │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          │  git add
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                     Staged                                    │
│                 (已暂存状态)                                   │
│                                                             │
│   文件已准备好被提交                                           │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          │  git commit
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                   Committed                                   │
│                 (已提交状态)                                   │
│                                                             │
│   修改已保存到仓库历史                                         │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          │  修改文件
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Modified                                   │
│                 (已修改状态)                                   │
│                                                             │
│   文件被修改但尚未暂存                                         │
└─────────────────────────────────────────────────────────────┘
```

## 分支模型

```
main:      A ─── B ─── C ──────────── F (合并后)
            \             \         /
             \             D ─── E  (功能分支)
              \           /
               ──────── G (另一个分支)
```

### 分支操作说明

| 操作 | 命令 | 效果 |
|------|------|------|
| 创建分支 | `git branch feature` | 创建新指针 |
| 切换分支 | `git checkout feature` | HEAD 指向新分支 |
| 合并分支 | `git merge feature` | 创建合并提交 |
| 删除分支 | `git branch -d feature` | 删除指针 |

## 合并过程

### 快进合并 (Fast-Forward)

```
合并前：
main:    A ─── B ─── C
                      \
feature:               D ─── E

执行：git checkout main && git merge feature

合并后：
main:    A ─── B ─── C ─── D ─── E
                              ↑
                          (快进)
```

### 三方合并 (3-Way Merge)

```
合并前：
main:    A ─── B ─── C ─── F
                      \
feature:               D ─── E

执行：git checkout main && git merge feature

合并后：
main:    A ─── B ─── C ─── F ─── M (合并提交)
                      \         /
feature:               D ─── E
```

## Rebase 过程

```
变基前：
main:    A ─── B ─── C
                      \
feature:               D ─── E

执行：git checkout feature && git rebase main

变基后：
main:    A ─── B ─── C
                      \
feature:               D' ─── E'  (新提交)
```

**注意：变基会创建新的提交（D' 和 E'），与原来的 D 和 E 不同**

## 远程追踪

```
本地仓库                         远程仓库 (origin)
┌─────────────┐                ┌─────────────┐
│             │                │             │
│   main ─────┼────────────────┼─── main    │
│             │   git push     │             │
│   feature ──┼────────────────┼─── feature │
│             │                │             │
└─────────────┘                └─────────────┘

git fetch: 同步远程分支信息
git pull:  fetch + merge
```

## 常用命令图解

### 提交流程

```
修改文件
    │
    ▼
git status  ──── 查看修改了哪些文件
    │
    ▼
git add .   ──── 暂存所有修改
    │
    ▼
git status  ──── 确认暂存的文件
    │
    ▼
git commit -m "message"  ──── 提交到仓库
    │
    ▼
git push    ──── 推送到远程
```

### 分支工作流

```
1. git checkout main          ──── 切换到主分支
2. git pull                   ──── 获取最新代码
3. git checkout -b feature    ──── 创建功能分支
4. [编写代码]                  ──── 进行开发
5. git add .                  ──── 暂存修改
6. git commit -m "feat: xxx"  ──── 提交修改
7. git push -u origin feature ──── 推送分支
8. [创建 Pull Request]         ──── 请求合并
9. [代码审查]                  ──── 审查代码
10. git checkout main         ──── 切换回主分支
11. git merge feature         ──── 合并功能分支
12. git push                  ──── 推送到远程
13. git branch -d feature     ──── 删除功能分支
```

## 冲突图解

```
冲突发生时：
┌─────────────────────────────────────────────────┐
│ <<<<<<< HEAD                                      │
│ 这是当前分支的修改                                  │
│ =======                                           │
│ 这是要合并的分支的修改                               │
│ >>>>>>> feature                                   │
└─────────────────────────────────────────────────┘

解决方法：
1. 手动编辑文件，选择保留的内容
2. 删除冲突标记 (<<<<<<, =======, >>>>>>>)
3. git add 标记为已解决
4. git commit 完成合并
```

## 提交历史图解

### 线性历史

```
A ─── B ─── C ─── D ─── E  (main)
```

### 分支历史

```
A ─── B ─── C ─── F ─── G  (main)
      \         /
       D ─── E            (feature)
```

### 查看历史命令

```bash
# 简洁模式
git log --oneline
# 输出：E G F C B A

# 图形化模式
git log --oneline --graph --all
# 输出：
# * E (main)
# * G
# |\
# | * F
# |/
# * C
# |\
# | * D
# |/
# * B
# * A
```
