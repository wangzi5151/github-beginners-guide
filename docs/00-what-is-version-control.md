# 第一章：什么是 Git 和 GitHub

## 1.1 版本控制概述

### 什么是版本控制？

版本控制是一种记录一个或若干个文件内容变化，以便将来查阅特定版本修订情况的系统。简单来说，它能够帮你记录每次文件的改动，方便你查看历史记录、回退到某个版本、或者多人协作。

**举个例子：**

假设你在写一篇论文，可能会遇到这样的情况：

```
论文_初稿.docx
论文_修改1.docx
论文_修改2.docx
论文_最终版.docx
论文_最终版_真的最终版.docx
论文_打死也不改了版.docx
```

这种方式非常混乱，而且容易出错。如果有版本控制系统，你可以：

1. 只保留一个文件
2. 每次修改都记录一个版本
3. 随时查看历史版本
4. 轻松回退到任何一个版本
5. 多人同时编辑同一个文件

### 为什么需要版本控制？

| 场景 | 没有版本控制 | 有版本控制 |
|------|-------------|-----------|
| 个人项目 | 文件越来越多，命名混乱 | 自动管理版本，清晰明了 |
| 团队协作 | 文件冲突，覆盖他人代码 | 自动合并，保留修改记录 |
| 回退修改 | 手动复制粘贴 | 一键回退到任何版本 |
| 追溯问题 | 不知道谁改了什么 | 完整的修改历史记录 |
| 多人开发 | 文件锁死，无法并行 | 并行开发，智能合并 |

### 版本控制系统的分类

**1. 本地版本控制系统**

最简单的版本控制方式，使用数据库记录文件变更。

```
优点：简单
缺点：只能在本地使用，无法协作
代表：RCS
```

**2. 集中式版本控制系统**

有一个中央服务器，所有客户端连接到服务器获取最新代码。

```
优点：可以多人协作
缺点：服务器单点故障，需要联网
代表：SVN、CVS
```

**3. 分布式版本控制系统**

每个人都有完整的代码仓库，可以在本地进行所有操作。

```
优点：离线工作，无需中央服务器，速度快
缺点：占用存储空间
代表：Git、Mercurial
```

## 1.2 Git 简介

### Git 是什么？

Git 是目前世界上最先进的分布式版本控制系统，由 Linus Torvalds（Linux 之父）在 2005 年创建。

**Git 的特点：**

1. **速度快**：大多数操作在本地完成，速度极快
2. **分布式**：每个人都有完整的仓库副本
3. **数据完整性**：所有数据都经过 SHA-1 哈希校验
4. **分支支持**：创建和切换分支非常快速
5. **非线性开发**：支持强大的分支和合并功能

### Git 的诞生故事

2005 年，Linus Torvalds 为了管理 Linux 内核开发，需要一个版本控制系统。当时使用的 BitKeeper 停止了免费授权，于是 Linus 花了大约两周时间用 C 语言编写了 Git 的第一个版本。

Git 的名字来源于英国俚语"Git"，意思是"令人讨厌的人"，Linus 觉得这个名字很有趣。

### Git 的工作原理

Git 通过快照的方式管理文件：

```
第一次提交：完整快照
第二次提交：只保存变化的部分
第三次提交：只保存变化的部分
```

**工作区、暂存区、仓库的关系：**

```
工作区 (Working Directory)
    ↓ git add
暂存区 (Staging Area)
    ↓ git commit
仓库 (Repository)
```

## 1.3 GitHub 简介

### GitHub 是什么？

GitHub 是一个基于 Git 的代码托管平台，提供 Web 界面，让开发者可以方便地管理代码、协作开发。

**GitHub 不仅仅是代码仓库，它还包括：**

- **Issues**：问题追踪系统
- **Pull Requests**：代码合并请求
- **Actions**：自动化工作流
- **Projects**：项目管理看板
- **Discussions**：社区讨论
- **Packages**：包管理
- **Pages**：静态网站托管
- **Copilot**：AI 编程助手

### Git 和 GitHub 的关系

```
Git（版本控制工具）  ≠  GitHub（托管平台）
    ↓                      ↓
  本地使用              云端服务
  命令行操作            Web 界面 + API
  管理代码历史           协作 + 社交功能
```

**简单来说：**
- **Git** 是一个安装在电脑上的软件，用于管理代码版本
- **GitHub** 是一个网站，使用 Git 作为底层工具，提供协作和社交功能

### 为什么选择 GitHub？

1. **行业标准**：超过 1 亿开发者在使用
2. **免费方案**：个人仓库完全免费
3. **生态丰富**：大量的集成和插件
4. **学习资源**：海量的开源项目可以学习
5. **简历加分**：活跃的 GitHub 主页是技术能力的证明
6. **AI 功能**：内置 Copilot AI 编程助手

## 1.6 常见误解

**误解 1：Git 只能用命令行**
事实：Git 有很多图形化工具，如 GitHub Desktop、GitKraken、VS Code 集成等。

**误解 2：Git 太难学了**
事实：Git 的基础命令只需要几小时就能学会，高级功能可以慢慢学习。

**误解 3：GitHub 只能托管代码**
事实：GitHub 可以托管任何文件，包括文档、图片、数据等。

**误解 4：只有开源项目才需要 GitHub**
事实：很多公司内部也使用 GitHub 进行项目管理。

**误解 5：Git 会占用很多空间**
事实：Git 使用增量存储，只保存变化的部分，非常节省空间。
